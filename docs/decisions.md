# Decisions

Every decision here has an `.ia` record in `.ia/src/decisions.ia`, named in the Record column. The records are authoritative; this page is their index. Add the row and the record in the same change.

| **Run the handlers installed kits declare.** A kit may ship handlers.json (format 1: session handlers with their events, prompt, tool with phase pre or post and a tool-name match, and stop, each a .mjs script inside the kit with a timeout of at most 25 seconds). scripts/handlers.mjs runs them from SessionStart (every source), UserPromptSubmit, PreToolUse and PostToolUse on edits and shell commands, and Stop, only for installed kits (this plugin's config/kits and <IA home>/kits) whose folder holds the script, so a fetched release, which carries no executables, never runs one. | **Vendor the kits a kit depends on.** A kit release's .ia/release.json dependencies other than inventarch/language name a kit id and range. ## Kit trust and process hygiene (2026-10-31)

| Choice | Standing | Record |
|---|---|---|
| **Trust kit code by publisher and recorded digest.** A kit may run code (a handlers.json run script, an onwrite.json command or a checks.json command) only when its publisher, the kit id's namespace, with which a .ia/release.json publisher field must agree, is on the plugin's config/trusted-publishers.json, which ships as inventarch alone, and its sources digest equals its latest release's recorded sources, with .ia/release.json naming that release; a handler's run script must also be a declared asset. Any other kit, and a kit with no recorded release, is data only: a handler entry may carry a context text, delivered as additionalContext with no process; its run entries and onwrite.json commands are skipped, its checks are refused with IA-CORE-KIT-UNTRUSTED, and the SessionStart answer names each such kit once, with why. A pre handler of a kit whose publisher is not on the list never blocks. In a governed workspace a trusted pre handler that fails, times out or answers past the output cap refuses the call, and an altered gate refuses every pre-tool call: while a kit whose id names a trusted publisher declares a pre handler whose code the trust check refuses (its bytes are not its recorded release, or its script is not a declared asset), each such call is refused, naming the kit and the fix, which is to reinstall its recorded release with node <ia plugin>/scripts/kit.mjs add --from <release> --apply or to remove .ia/governance.json. Nothing extends the list at run time. Every child the three runners start gets an allowlisted environment (never NODE_OPTIONS or NODE_PATH), its process tree is killed on its deadline, and a hook child keeps at most 256 KiB of stdout and of stderr: hygiene, not a sandbox. | Operator ruling; made | `public-kit-trust` |

## Repository protection and releases (2026-11-01)

| Choice | Standing | Record |

| **Release plugins from pending notes through an operator-started release pull request.** A pull request that changes a plugin's shipped files adds a release note, releases/pending/<id>.json (format inventarch-marketplace.release-note.v1: bump patch, minor, major or none, a title, a summary and the plugins it names), with node tools/release.mjs note, and never bumps the plugin by hand; consistency --base refuses a shipped change unless the plugin's version rose or a note new or changed since the base names it, and release.mjs check, a gate, refuses a malformed note. The release pull request workflow, started only by an operator's dispatch from main, runs release.mjs version --write (the highest bump among each plugin's notes; both manifests, sources.lock.json pluginVersion and the CHANGELOG entry; releases/changesets/<plugin>-<version>.json; the consumed notes removed) and selection.py --write with GITHUB_TOKEN and no dependency install, force-pushes release/next, opens its pull request as a draft or updates the existing pull request without changing its readiness, and dispatches Gates on it. | **Protect main and the tags with rulesets.** Three repository rulesets, kept as JSON under .github/rulesets/ and applied through the GitHub API. main (no bypass) on the default branch: no deletion, no force push, changes only through a pull request with every review thread resolved, stale approvals dismissed, merge commits as the only merge method, and the Gates (ubuntu-latest) and Native verified (ubuntu-latest) checks passing on a branch up to date with main. main-review: a code owner's review (.github/CODEOWNERS), with the operator's account as the only bypass, in pull_request mode, so the operator's and the operator's agents' own pull requests are never blocked. tags (no bypass): no tag may be deleted, moved or force-updated.
