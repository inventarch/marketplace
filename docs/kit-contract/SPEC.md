# Public kit contract expectation baseline

Task and spec: `kit-contract-public-baseline`; plan: `kit-contract-qualification`; [issue 21](https://github.com/inventarch/marketplace/issues/21). Authoring attribution: InventArch.

The baseline supplies proposed public expectations before a native contract or checker is implemented. It consists of `expectations.json` and `context.md`, reviewed together. It is not shipped in the plugin or any kit. Version 0.1.0 is a proposal, not a published contract release. All behavioral evaluators remain unavailable.

The four contracts must retain 14 requirements and 163 individually attributed cases: candidate conformance (8/86), qualification inputs (2/34), programme audit (1/6) and checker execution (3/37). Preserve every stable contract/requirement/case identity, association, kind, given, request, expected outcome and grammar reference. A repeated semantic variant under another requirement remains a separate obligation. The complete normative context accompanies the data, including applicability, trusted assessment selection, payload identity, oracle independence, bootstrap, consumer verification, current eligibility and custody.

The repository test reads these artifacts as inert data. It checks inventory and required fields, and compares every normative JSON field and association against a fixed semantic SHA-256 pin. Canonicalization recursively sorts object keys, preserves array order and uses UTF-8 compact JSON; it performs no Unicode normalization. The context pin covers all UTF-8 text after CRLF-to-LF normalization only. Missing data, duplicate or reassigned cases, changed context or expectations, incomplete requirement information and fabricated evaluator standing must fail. Pins are constants in the test, never recalculated from the candidate at runtime. No automatic snapshot-update command is provided.

Negative controls mutate copies only. Each first verifies the unchanged baseline, then demonstrates rejection of a specific loss or drift, including changes preserving all counts. These tests establish baseline integrity, not execution of the 163 scenarios. They establish neither safe-publication screening, independent approval authenticity, native admission, runtime conformance, final-artifact verification, checker eligibility nor release authority. They are repository tests, not shipped checker code.

Independent review must compare the proposed public semantics against the governing intent before the baseline is frozen for lowering. Any changed expectation requires an explicitly reviewed versioned delta; changing the data and its test pin together is not approval. First adoption also requires public review/approval evidence tied to the exact public content digests. Private source provenance is not a required public qualification input.

Publication remains pending until authorized publisher screening covers the complete publication payload against the operator-maintained private-identity list held outside this repository. A missing list is not evaluated, never a pass. This includes test, review and provenance files; sensitive screening inputs remain private. The later lowered/generated artifacts require their own screening. Local integrity tests and generic-label review cannot substitute for this obligation.

Exact public catalogue exports, native representation, executable checker ownership/profile/binding, behavioral fixtures and approvals, first-checker bootstrap, eligibility channel and both publication consumers remain subsequent qualification work. Passing this slice does not close those tasks or permit new kit cuts. No merge or release is part of this task.
