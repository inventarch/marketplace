# Publisher identity screening

Task/spec `publication-identity-screening`, plan `kit-contract-qualification`, [issue 22](https://github.com/inventarch/marketplace/issues/22). Attribution: InventArch. Catalogue policy owns this publisher-side check; this repository's maintainer tool implements it. No new system, word, installed kit executable or shared conformance checker is introduced.

`tools/check-identities.mjs` screens an explicit frozen text publication payload. It is a development/maintainer operation, not an integrated kit packing gate. It never packs, pushes, publishes, executes payloads, fetches dependencies or approves a registry. General public conformance callers do not supply this private publisher input.

The trusted operator supplies `root` (a dedicated frozen payload directory), external `manifestPath` and `registryPath`, their exact raw-byte SHA-256 pins, and mandatory `publicRoot` (the actual public checkout; never inferred from the detached payload root). Both input documents must resolve outside root and publicRoot, including aliases, and must be regular files with one hard link. Missing or invalid publicRoot is not evaluated. The operator is responsible for truthful root selection. The checker verifies these pins, not an input's assertion that it is approved. An accepted registry digest must come from independently reviewed operator policy outside the candidate. A test fixture pin or a digest computed from a newly proposed list is not organizational acceptance. The operator remains responsible for registry custody and completeness; filesystem location alone is not an access-control guarantee.

Registry format 1 has exactly `format`, `scope`, `entries`; scope is nonempty text identifying the approved publication domain. Entries have exactly `id`, `value`, both nonempty strings; IDs and normalized values are unique, and values have at least four characters. An empty registry is not evaluated. The private registry's separate provenance record identifies its owner, source inventory, exclusions, reviewed digest and acceptance evidence. None of that private corpus is bundled with this tool.

Manifest format 1 has exactly `format`, `scope`, `files`. Its scope must equal the selected registry's scope. Every file row has exactly `path`, `sha256`, `bytes`, `mediaType` (`text` or `json`). Paths are unique portable relative slash paths: no traversal, empty segments, backslashes, drives, controls, reserved device names or trailing dots/spaces. Case-colliding paths refuse on every platform. JSON files must select json mode. The file set must equal the entire payload directory, including dotfiles: omissions, additions and missing files refuse. Directory/file symlinks and hard-linked files refuse. Files must be regular, within the root, bounded and exactly match their declared byte lengths and raw SHA-256. Registry and manifest themselves are strict UTF-8, pretty JSON with two-space indentation and a final newline (CRLF representation allowed); round-trip equivalence rejects duplicate keys. Maximum input document/file size is 4 MiB, maximum total payload 32 MiB and maximum file count 1024. Registry and manifest cannot select larger limits.

Supported payload extensions are `.md`, `.txt`, `.ia`, `.json`, `.js`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.yml`, `.yaml`, `.html`, `.css`, `.svg`; unknown/binary/archive formats are not evaluated. Payloads must be strict UTF-8, with no NUL; a JSON payload must parse. Matching is case-insensitive literal substring matching after NFC normalization and slash normalization. Screen every manifest path and raw content. For JSON also screen every decoded string token, including keys and duplicate-key values, so JSON escapes cannot hide a match. Do not execute code or infer arbitrary base64, compression or semantic encodings. A clean lexical result is not a universal disclosure guarantee; independent semantic projection review remains required. Short ambiguous terms and necessary public namespaces must be resolved in the private registry's reviewed classification, never by a candidate exemption list.

The API returns `passed`, `refused` or `not-evaluated`, a stable reason code, exact manifest/registry digests and coverage. Missing, unreadable, malformed, empty, unpinned, scope-mismatched or internally placed input documents are not evaluated; no partial pass. Payload drift, aliases and identity matches refuse; unsupported payload formats or malformed encoding are not evaluated. No aggregate pass is emitted until every file is checked. Match details identify entry IDs, values, paths and match surface in the private API result. The CLI prints only status, code, file/byte coverage and the public manifest digest; it never prints private matches, registry digests or arbitrary exception text. Detailed reports can be retained by an authorized caller of the API in private storage. Missing CLI flags/unknown/duplicate flags fail with usage and a nonzero exit. CLI exit codes: passed 0, refused 1, not-evaluated 2.

Evidence describes the exact bytes read. It is not a portable authorization receipt; the publisher must keep the frozen payload unchanged and re-screen any changes, regenerated outputs or a different artifact set. This slice does not authenticate GitHub approvals, enforce packing integration or prove the operator registry exhaustive. No approval status field in a candidate registry can grant authority. All tests use synthetic identities and independent temporary directories, with no private production registry and no network.

## Exact result contract and limits

The fixed profile is literal text plus JSON string tokens. It does not render Markdown, HTML or SVG, decode character references/Markdown escapes, join soft line breaks, remove invisible format characters or interpret code. Tests retain synthetic examples demonstrating these limits; a passed lexical result must still be combined with semantic review of the exact payload. The caller must identify the actual checkout and other public copies; this tool checks only the two supplied roots and cannot discover every public worktree or infer ACLs.

Normalization is NFC, then ECMAScript toLowerCase, then NFC, then backslash-to-slash replacement, with no other folding or whitespace change. Minimum length is four Unicode code points after normalization. Registry values have at most 1024 code points; there are at most 256 entries. Portable path collision keys use this same normalization; paths reject control/format characters, exceed neither 2048 code units nor 64 segments, and every directory must contain a manifest-listed descendant. Empty manifests are not evaluated. A snapshot has at most 1024 directories. Input JSON nesting is limited to 64; payload JSON string tokens are inspected iteratively, with nesting limited to 64 too. Input BOMs are preserved by decoding and rejected by JSON parsing. Pins are lowercase 64-character hexadecimal hashes over raw bytes. Mixed LF/CRLF input documents are accepted only when normalization round-trips to the specified pretty JSON representation.

The API returns a result rather than throwing for bad options, I/O or unsupported data. Hash and scan each payload from the same buffer; parse each input from the buffer whose pin was verified. Compare file identity, link count, size and modification/change timestamps before and after reading; changes refuse. No check can authorize a later mutation. Directory names not represented by a manifest descendant refuse instead of being ignored.

Evaluation order is roots/input custody, registry pin/shape, manifest pin/shape/scope, manifest path/media constraints and declared resource bounds, directory traversal/aliases, exact file/directory coverage, then each sorted file's size/hash/format and identity matches. No match result is returned until all files pass validation; an unsupported file therefore prevents a complete screen even when another file matches. A result's coverage counts only successfully validated buffers; an early failure can have partial or zero coverage, never a partial pass. Findings enumerate matching entry/file/surface triples once, with surfaces path, text or json-string. Internal failures disclose no exception text.

| Codes | Status |
|---|---|
| CLEAN | passed |
| PAYLOAD_MANIFEST, PAYLOAD_ALIAS, PAYLOAD_COVERAGE, PAYLOAD_DRIFT, IDENTITY_MATCH | refused |
| ROOT_INVALID, INPUT_CUSTODY, INPUT_PIN, INPUT_UNAVAILABLE, INPUT_SCOPE, REGISTRY_LIMIT, MANIFEST_LIMIT, REGISTRY_INVALID, MANIFEST_INVALID, PAYLOAD_LIMIT, PAYLOAD_UNAVAILABLE, PAYLOAD_FORMAT, INTERNAL_ERROR | not-evaluated |

Malformed document shape is not-evaluated; a structurally readable manifest violating publication path/media constraints is refused with PAYLOAD_MANIFEST. CLI required flags are --root, --public-root, --registry, --registry-sha256, --manifest and --manifest-sha256, each once with a value. Stdout is one JSON object with exactly status, code, coverage and manifestSha256 (null until verified). Usage failures return 2 with a constant usage message on stderr and no stdout. The private API record also binds the registry digest and findings; publisher acceptance must retain it privately with operator registry acceptance and semantic review evidence. Public CLI output alone does not prove authorized screening.
