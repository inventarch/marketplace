# Changelog

## 1.3.0

Bundle the InventArch account connector.

- **Bundle the InventArch account connector.** The core now ships the InventArch account connector (MCP server inventarch, with the public Claude Code OAuth client), so signing in through /mcp is enough: ia:init then lists the kits the account offers, downloads each through its signed URL, verifies the SHA-256, installs it with kit.mjs add --from and binds it as the kit recommends. The session-start account offer is now a one-line pointer to that sign-in. Also fixes kit.mjs add --from on an archive whose absolute path has a drive letter under GNU tar.

## 1.2.0

Re-cut on IA 3.5.0 (decision `public-cli-3-5-0`, which supersedes `public-cli-3-4-1`).

- Pins `@inventarch/cli` 3.5.0 everywhere the core, its tests and its tools pinned 3.4.1 (`scripts/lib/cli.mjs`, the closure modules, the native runner and verifier, the skills and documents). The language base is unchanged: `inventarch/language` 3.2.0, archive 7b36e4b4.
- The IA door launcher starts `npx -y @inventarch/mcp-door@3.5.0`.
- The qualified runtime cohort is regenerated as `config/qualified-runtime-3.5.0.json` (24 packages, checked against the registry integrity in the root lock); `config/qualified-executors.json` follows the changed `lib/cli.mjs`.
- Bundled kits re-cut with the 3.5.0 CLI: `ia-method` 0.7.1, `ia-kb` 0.9.1 and `ia-authoring` 0.1.1 (recorded releases are immutable, so a new patch version each). `ia-method`'s two case evaluators now name the public path `plugins/ia/tests/ceiling.test.mjs`.
- The upkeep agent ships (decision `public-upkeep-agent`): `agents/upkeep.md` and `scripts/upkeep.mjs` lose their spike framing and private reference, and state what they do and their limits.
- The lanes drop their `scripts/resolve.mjs` and `kit.mjs list` fallback (task `drop-door-fallback`, done). `@inventarch/mcp-door@3.5.0` was started over stdio and its `tools/list` holds `ia_session`, `ia_catalogue` and `ia_method` beside the read tools, so the lanes call only the door. `resolve.mjs` stays: `ia:init`, `ia:delegate`, the agents' packets and the kits' cases still use it.
- No kit code reaches outside its folder. `ia-authoring`'s `scripts/field-lint.mjs` and `scripts/probe.mjs` import the kit's own `scripts/lib/scratch.mjs` (declared as an asset; the copy-workspace, CLI-resolution and capture code they used, no longer `../../../../scripts/lib/scratch.mjs`). The core's `scripts/lib/scratch.mjs` stays for the core. `ia-kb`'s evaluators (`kit-kb` and `kit-kb-ingestion`) name the public `plugins/ia/tests/` paths instead of `inventarch/tests/`.
- The IA door is on under Codex (decision `public-door-codex`): the Codex manifest names `./.codex-mcp.json` (`node ./scripts/door.mjs`, `cwd` `./`) instead of `"mcpServers": {}`. Codex does not expand `${CLAUDE_PLUGIN_ROOT}`, so the Claude `.mcp.json` stays as it was. `tools/validate.py` holds both door files exact and `tools/smoke-codex.mjs` starts the door through Codex and requires `ia_session`, `ia_catalogue` and `ia_method`. Kit handler hooks stay off in Codex.

## 1.1.0

The lanes go through the IA door, kits run handlers and depend on other kits, only trusted kits run code, and governance arrives as a kit (decisions `public-door-mcp`, `public-kit-handlers`, `public-kit-trust`, `public-kit-dependencies`, `public-delegate`, `public-governance-probe` and `public-core-hooks`). ia-kb 0.9.0, not yet published, is re-recorded from 57ebf44 with the knowledge-repository layout of the operator's ruling dec-132 (one `.ia/src`; one `@workspace` for a personal or single-team KB; for an organisation store one `@workspace` per department plus an organisation `@workspace` that also declares the root; `workspaces/<name>/` only for a workspace released or adopted on its own); ia-method 0.7.0 and ia-authoring 0.1.0 stand.

- The plugin ships the IA door as its MCP server `ia` (`.mcp.json`: `node scripts/door.mjs`, a launcher that starts `npx -y @inventarch/mcp-door@3.4.1` never through a shell (on Windows, where `npx` is a `.cmd` shim, it runs npm's `npx-cli.js` with `node`), with stdio passed through and `IA_KITS_DIR` set to the bundled kits). Claude Code names its tools `mcp__plugin_ia_ia__<tool>`. Codex reads a plugin's `.mcp.json` too, so the Codex manifest keeps the door off with `"mcpServers": {}` until it is qualified there.
- The lanes call `ia_session` once per session, then `ia_catalogue {lane}` to choose a key and `ia_method {key}` for the packet. Until `@inventarch/mcp-door` ships `ia_method`, they fall back to `scripts/resolve.mjs` and `kit.mjs list`.
- The reader, checker and worker allowlists name the door's tools by their plugin-scoped names; the checker now has the door tools too. The old `mcp__ia-workspace` entries never matched a plugin server and are gone.
- The SessionStart bootstrap also runs on `compact`, and then re-injects the current task pin's summary and how to resolve the same method again.
- Kit handlers: a kit's `handlers.json` declares session, prompt, tool (pre or post, with a tool-name match) and stop handlers, and `scripts/handlers.mjs` runs them from SessionStart (every source), UserPromptSubmit, PreToolUse, PostToolUse and Stop. Only installed kits whose folder holds the script run; each kit's context is capped at 2,000 characters; a pre block is honoured only with `.ia/governance.json`; with no handler declared every hook is a silent no-op. `onwrite.json` runs as tool post handlers, from the kits in `<IA home>/kits` too. `handlers.json` is a sidecar the sources digest covers, and `kit.mjs check` refuses a handler script that is not a declared asset.
- Kit trust (decision `public-kit-trust`, `scripts/lib/trust.mjs`): a kit runs code through `handlers.json`, `onwrite.json` or `checks.json` only when its publisher, its id's namespace, is on `config/trusted-publishers.json` (`inventarch` alone; nothing extends it at run time, since an agent with a shell could approve itself) and its sources digest is its latest recorded release's; a handler's script must also be a declared asset. Any other kit is data only: a handler entry may carry a `context` text, delivered with no process run; its `run` entries and on-write commands are skipped, its checks refuse `IA-CORE-KIT-UNTRUSTED`, and SessionStart names each such kit once with why. A `pre` handler of a kit whose publisher is not on the list never blocks; a trusted one that fails in a governed repository still refuses the call, now also when it times out, answers past the output cap or is still running when the hook's budget ends. An altered gate fails closed: in a governed repository, while a kit whose id names a trusted publisher declares a `pre` handler the trust check refuses (its bytes are not its recorded release, or its script is not a declared asset), every pre-tool call is refused, and the reason and the session-start notice name the kit and the fix (reinstall it with `node <ia plugin>/scripts/kit.mjs add --from <release> --apply`, or remove `.ia/governance.json`). The governance notice names an installed governance kit that may not run, and `kit.mjs check` reports `runsCode` per kit. A retained task pin carries the trusted list too.
- Process hygiene, not a sandbox (`scripts/lib/hygiene.mjs`): every child the handler, on-write and check runners start gets an allowlisted environment (the command path, the OS and home folders, locale, git's configuration lookup, `CLAUDE_PID`, and `IA_*` without credential-like names; never `NODE_OPTIONS` or `NODE_PATH`), its process tree is killed on its deadline (a POSIX process group, or `taskkill /T` on Windows), and a handler or on-write child keeps at most 256 KiB of stdout and of stderr. The handler and on-write runners are asynchronous now, and their hook entry points wait for them.
- The governance probe no longer looks for a plugin: in a repository with `.ia/governance.json` where no installed kit declares governance handlers (a tool pre handler), it says "this repository is governed; add the ia-governance kit (`ia kit add`)".
- Kit dependencies: a kit whose `.ia/release.json` depends on another kit finds it carried by the plugin, in `<IA home>/kits` or next to it, and adoption (`kit.mjs add`), `add --from` and the restored read root vendor the dependency's recorded release with `ia install --catalog`. `add --from` installs a dependency it finds only next to the kit into `<IA home>/kits` alongside it, dependencies first (the result lists them under `alongside`), so the installed kit resolves it from the home.
- Release versions are strict semver everywhere the core reads or writes one: the release index (either format), each `releases/<version>.json`, which a row must name exactly, `.ia/release.json` and the `add --from` install target, which must stay inside `<IA home>/kits`. `add --from` refuses a kit folder that holds a link, and a handler runs only when its script, links followed, sits inside its kit.
- The user-invoked `ia:delegate` hands one packet-driven step to `codex exec` or `claude -p` with the door and the packet inline, one level deep (`IA_DELEGATION_DEPTH`), with a timeout. It is off until the person sets `"delegation": true` in `~/.ia/config.json`.

## 1.0.0

The first public release, cut on 2026-10-30 from InventArch's internal catalogue with fresh history (decisions `public-catalogue-cut` and `public-core-1-0-0`). It is a breaking release: repositories bound to a kit this core no longer carries must rebind.

- The plugin is `ia` (`ia@inventarch`; decision `public-plugin-ia`). Its model-invocable skills are the three lanes, `ia:work`, `ia:knowledge` and `ia:delivery`; the former router became the user-invoked `ia:init`, with the CLI-rendered plugin's init steps merged in, beside a new `ia:doctor`. Agents are `ia:reader`, `ia:checker` and `ia:worker`.
- Licence Apache-2.0; repository `inventarch/marketplace`.
- The bundled kits are exactly the public defaults: `ia-method` 0.7.0 (Work), `ia-kb` 0.9.0 (Knowledge) and `ia-authoring` 0.1.0 (Delivery; it replaces the retired `inventarch/host-authoring-kit` and `inventarch/catalogue-authoring-kit`). Each lane's entry capability is a whole four-phase procedure; Knowledge `place` maps to the plan phase; the core names no whole-procedure activity of its own.
- Kit lookup in two places: `config/kits`, then `<IA home>/kits/<kit>/<version>/`.
- `scripts/kit.mjs` user verbs: `list`, `add` (also `add --from <folder|archive>`), `bind`, `upgrade`, `repin`, `rebind` and `check`, each previewing unless `--apply` and validating before it writes; `root`, `status` and `adopt` stay.
- Releases format 2: the core reads a release index and `releases/<version>.json` (and still format 1); `lib/releases.mjs` converts losslessly; release history is left out of the implementation digest and the method closure capture.
- The SessionStart hook offers an InventArch account once per session at startup, never blocking, with no network and no token (suppressed by `"accountOffer": false` in `~/.ia/config.json`, `IA_NO_ACCOUNT_OFFER=1` or `CI`), and says once when a repository has `.ia/governance.json` but the governance plugin is not installed.
- Pins `@inventarch/cli` 3.4.1, with a regenerated qualified runtime cohort.
